# 2D textures, lighting and camera participants

The native world owns sprite material selection and global light state. Presentation extraction resolves global lighting into the existing quad tint. Sprite and dynamic-quad draws use the same renderer, attachments and ordering. No render stage is added.

## Texture sampling

`SceneTexture::with_sampler(TextureSampler)` sets sampling on an individual texture. `TextureFilter` selects Point, Bilinear or Trilinear. `TextureWrap` selects Repeat, Clamp or Mirror independently on U and V. Point sampling selects the nearest texel and mip. Bilinear filters texels linearly within the nearest mip. Trilinear also blends between mip levels.

A texture without an explicit sampler uses linear texel and linear mip filtering with repeat wrapping. Explicit Bilinear remains distinct from that unspecified state. Texture identity determines both its uploaded texture and sampler, including when multiple textures appear in one frame. Dynamic quad UVs may be any finite coordinates; the sampler resolves out-of-range coordinates. Dynamic and native sprite uploads consume each texture's sampler. Anisotropic filtering is outside the dynamic sampling contract; these draws remain isotropic. Resident mesh materials and impostor atlases ignore per-texture filter and wrap settings. They use linear minification, magnification and mip filtering with repeat wrapping for every channel.

`SceneMaterial::with_anisotropy(TextureAnisotropy)` sets the maximum footprint ratio for the material's shared sampler, including albedo, normal, roughness/metallic, ambient occlusion, emission and impostor auxiliary maps. `TextureAnisotropy::new` accepts 1, 2, 4, 8 or 16 and rejects other levels with `SceneValidationError`. Materials default to 1. Equal material levels share a sampler within an upload; different levels use different samplers even when their albedo handle is identical. No filter or wrap setting changes when the level changes. Terrain anisotropy is not implemented for sources or cached pages; [#347](https://github.com/acoliver/real-disunity/issues/347) tracks both paths. See [terrain pages](terrain-pages.md) for their sampling limitations.

Device clamping follows wgpu 30's sampler contract: the requested ratio is capped at 16 when the adapter supports anisotropic filtering and reduced to 1 when its downlevel flags omit that capability. wgpu applies this at sampler creation; it exposes no per-device numeric maximum. The authored value remains unchanged. Filtering bytes above 1 are backend-dependent. The grazing-plane regression independently derives the longer projected footprint axis and checks increased detail across the shorter axis in material channels. Resident regression images cover explicit default and Point/Clamp texture settings at material level 1.

## Global lighting

Set `SpriteRenderer::lighting` to `SpriteLighting::Global` for the built-in lit sprite material. Unlit is the default. Managed renderers select the same native state through `SpriteRenderer.sharedMaterial = Material.SpriteLit` or `Material.SpriteUnlit`; `Material(BuiltinSpriteMaterial)` validates the typed choice. The sprite ABI and both presentation exports preserve that identity while native extraction applies lighting once. Add `ComponentDesc::GlobalLight2d` with color, nonnegative intensity and signed target sorting-layer IDs. Enabled lights on active, published objects contribute RGB multiplied by intensity. Contributions sum independently for each targeted layer and multiply the sprite's linear RGB. Sprite alpha is unchanged.

When no active lights exist, lit sprites equal unlit sprites. When active lights exist but none target a sprite's sorting layer, that lit sprite receives zero RGB. Unlit sprites ignore all lights. Light intensity can produce HDR RGB; the target format determines clipping or encoding. An extraction-local layer summary scans lights once per extraction. Non-finite accumulation fails with a typed native presentation error.

Tilemaps select lighting the same way. `Tilemap::lighting` is the `TilemapRenderer` material, unlit by default, and extraction tints lit tiles with the lights summed for the tilemap's sorting layer, after multiplying the tilemap and tile colors. Managed hosts set it with `DisunityHost.SetTilemapMaterial(tilemap, Material.SpriteLit)`; the scene loader applies the authored material. `disunity_tilemap_lighting_read` and `_write` carry it across the ABI, and tilemap layout writes keep it.

The supported light type is Global and the supported blend style is 0, multiply. Other light types, other blend styles and `ShadowCaster2d` return `ComponentError::UnsupportedField`. Rejected component edits preserve the previous state. Managed equivalents are `UnityEngine.Rendering.Universal.Light2D` and `ShadowCaster2D`. Unsupported managed light settings throw `UnsupportedLight2DException` with the field name.

## Camera participants

`AudioListener`, `GUILayer` and `FlareLayer` are native enabled components with ordinary hierarchy, clone and lifetime behavior. Their managed types derive from `Behaviour`. There is no audio output or source implementation; a listener without sources is silent. The managed listener exposes global volume and pause controls. The host writes zero/multiple active-listener diagnostics to stderr after a completed managed `Step`, once per diagnostic transition. It resets that state on load/unload. `DisunityHost.AudioListenerDiagnostic` also permits inspection without rejecting the world.

`UniversalAdditionalCameraData` is native state with a managed `MonoBehaviour` surface. The current pipeline accepts base-camera rendering without post-processing, antialiasing, shadow rendering, NaN filtering, dithering or forced depth/color texture copies. Depth/color overrides accept Off and UsePipelineSettings because the current pipeline requests neither copy. Volume masks and XR permission are retained; neither activates a rendering feature. Enabling an unsupported feature returns a typed error naming its field. The managed exception is `UnsupportedCameraSettingException`.

The managed `CameraOverrideOption` values are Off = 0, On = 1, UsePipelineSettings = 2. Boolean false selects Off = 0. Forced On rejects with the field-specific error and preserves the preceding state. Defaults describe the admitted subset, including `renderShadows = false`, rather than all Unity defaults. `SetRenderer(-1)` and `SetRenderer(0)` are equivalent only in this single-renderer setup.

Settings are validated before publication. Native code can inspect and update the admitted camera settings with `get` and `set`; the ABI uses the same validated operations. Camera lens and clear settings stay on the `Camera` component, separate from additional camera data, and cross the ABI as `DisunityCamera` through `disunity_camera_read` and `_write`.

## Lights

`ComponentDesc::Light` is the native 3D light: `presentation::Light` holds `enabled` and a `LightSettings` record (kind, color, intensity, range, spot and inner spot angle, shadow mode, strength, bias, normal bias and near plane, culling and rendering layer masks, bounce intensity, color temperature, cookie size and texture id, bake type). `LightSettings::validate` rejects negative or non-finite intensity, range, bounce intensity and cookie size, a color temperature that is not above zero, non-finite color and shadow biases, a spot angle outside 1 through 179, an inner angle outside 0 through the spot angle and a shadow strength outside 0 through 1. `normalized` first clamps those angles and the strength (a NaN is rejected) and lowers the inner angle with the spot angle; `disunity_light_write` normalizes before it stores. An object has at most one light. Clones copy the settings, and a disabled light keeps them. No frame draws a light yet. The ABI is `DisunityLight` with `disunity_light_create`, `_read` and `_write`; the managed `Light` is a `Behaviour` that reads the record, changes one field and writes it back.

## Tests

Synthetic GPU tests assert exact sRGB RGBA bytes at 1x and 4x MSAA for point and bilinear filters, wrap modes, independently sampled textures, summed global lights, untargeted layers, disabled lights and absent lights. Test geometry covers the inspected pixels at every sample position. Constant sampling coordinates isolate texel and wrap cases; a contrasting two-mip case uses fractional LOD to distinguish Bilinear from Trilinear and compares complete unspecified/default images. Chosen linear colors map away from sRGB rounding boundaries. Feature-off tests compare complete images and pass identities, including StageIds.
