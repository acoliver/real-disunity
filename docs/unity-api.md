# Supported UnityEngine API

`Disunity.Engine` implements a subset of the `UnityEngine` API. This page lists the types and members the assembly defines, grouped the way a game uses them, and says what each one does. A member described as stored or defined keeps its value and has no effect on the simulation or on a frame. A member that cannot work throws an exception, and the row names it: usually `NotSupportedException` with the member's name in the message, or `DisunityException` when the native world rejects a value. A type or member this page does not list is not covered here; read its source before relying on it.

The source of truth is `csharp/Disunity`. Each type lives in a file of the same name, so `csharp/Disunity/Physics2D.cs` holds `Rigidbody2D` and the 2D colliders. Writing scripts and hosting them is covered in [Writing C# scripts](csharp-games.md).

## Objects, components and lifecycle

These cover creating, finding and destroying things, which nearly every script uses.

| Type | Supported |
| --- | --- |
| `Object` | `Instantiate` (original; with parent; with parent and `worldPositionStays`; with position and rotation; with position, rotation and parent; with `InstantiateParameters`; with position, rotation and `InstantiateParameters`), `InstantiateAsync` (see [Assets](#assets-web-requests-json-and-command-buffers)), `Destroy(obj)` for game objects, components, `ScriptableObject`s and managed assets, `Destroy(obj, delay)` for game objects, `DestroyImmediate` for managed assets, game objects and components, `DontDestroyOnLoad`, `name`, `GetInstanceID`, `GetEntityId`, `FindObjectOfType`, `FindObjectsOfType`, `FindFirstObjectByType`, `FindAnyObjectByType`, `FindObjectsByType`, Unity-style null and equality checks on destroyed objects. `hideFlags` is stored and `MarkDirty` does nothing, since there is no editor. Searches find the active scene objects (game objects and components, or `Object` itself). A search for any other type, a search that includes inactive objects, and the obsolete `FindObjectsOfTypeAll` and `FindObjectsOfTypeIncludingAssets` throw `NotSupportedException`. These also throw `NotSupportedException`: `Destroy(obj, delay)` on a component or an asset, `DestroyImmediate` on a `ScriptableObject`, `Instantiate` with `worldPositionStays` true under a parent, `Instantiate` with `InstantiateParameters` in world space under a parent or with a valid `scene`, `Instantiate(Object, Scene)`, and `Instantiate` of an asset whose class cannot copy itself. `DontDestroyOnLoad` on a non-root object logs a warning and does nothing. |
| `GameObject` | `GameObject()`, `GameObject(name)` and `GameObject(name, params Type[])`, `name`, `tag`, `layer` (0 to 31, otherwise `ArgumentException`), `isStatic` (stored), `scene`, `sceneCullingMask`, `CompareTag`, `activeSelf`, `activeInHierarchy`, `SetActive`, `transform`, `gameObject`, `Destroy`, `Dispose`, `Find` (a name, or a path of names separated by `/`), `FindWithTag`, `FindGameObjectWithTag`, `FindGameObjectsWithTag`, `AddComponent<T>` and `AddComponent(Type)`, `GetComponent`, `TryGetComponent`, `GetComponents`, `GetComponentInChildren`, `GetComponentsInChildren`, `GetComponentInParent`, `GetComponentsInParent` (generic, `Type` and `List<T>` forms; the children and parent searches skip inactive objects unless `includeInactive` is true), `SendMessage`. `SendMessage` calls the named method, public or not, on each `MonoBehaviour` of an active object; with `RequireReceiver` and no receiver it logs an error, and an exception a receiver throws is logged. Most members of a destroyed game object throw `ObjectDisposedException`. `CreatePrimitive(type)` makes an object named after the type with a `MeshFilter` naming the shared mesh of that shape and a `MeshRenderer` with no material (the engine has no default material); it gets no collider, because 3D colliders cannot be attached yet. A type outside `PrimitiveType` throws `ArgumentOutOfRangeException`. `AddComponent` works for scripts and for `Camera`, `Light`, `Light2D`, `UniversalAdditionalCameraData`, `SpriteRenderer`, `Tilemap`, `TilemapCollider2D`, `Canvas`, `RectTransform`, `CanvasGroup`, `Rigidbody2D`, `BoxCollider2D`, `CircleCollider2D`, `AudioListener`, `GUILayer`, `FlareLayer`, `Animator` and `SortingGroup`. It throws `NotSupportedException` for `AudioSource`, the 3D physics components and any other type, such as `UnityEngine.UI.Text` (a host creates text with `DisunityHost.CreateText`). `AddComponent` honours `[RequireComponent]`, read on the type and its base types: before it creates the component it adds each required type the object has no component assignable to, recursively, so a required type's own requirements come first and the script's `Awake` sees the components it requires. A requirement on `Transform` adds nothing, and a requirement on `RectTransform` turns the object's plain transform into a `RectTransform` that keeps the parent, children, sibling index and local pose. A required type that is abstract or an interface with no matching component cannot be added, so the engine logs an error naming both types and adds the requesting component anyway (the engine's choice). Requirements that name each other add each type once. An attribute that names a type the engine lacks cannot be read (the runtime throws `TypeLoadException`, `FileNotFoundException` or another loader error): the engine reads each type level separately, logs one error naming the requesting type, the level and the cause, skips that level's requirements and still adds the other levels' requirements and the component (the engine's choice). A required native type the engine cannot create throws `NotSupportedException` as `AddComponent` of that type does. Scene and prefab loading build the components their plans list and do not add required ones. Refusing to destroy a component another one requires is not done. |
| `Component` | `gameObject`, `transform`, `name` (the game object's name), `tag`, `CompareTag`, `GetComponent`, `TryGetComponent`, `GetComponents`, `GetComponentInChildren`, `GetComponentsInChildren`, `GetComponentInParent` and `GetComponentsInParent`, with the same forms and results as on `GameObject` |
| `Behaviour` | `enabled` (not virtual, so a subclass's `base.enabled` reaches the component's own state), `isActiveAndEnabled`. The native behaviours (`Camera`, `Canvas`, `CanvasGroup`, `Collider2D`, `Light`, `Tilemap`, `AudioListener` and the other camera layers) derive from it and keep their enabled state natively, so a compiled game that sets `enabled` through `Behaviour` reaches that state. |
| `MonoBehaviour` | Messages `Awake`, `OnEnable`, `Start` (also as a coroutine), `FixedUpdate`, `Update`, `LateUpdate`, `OnDisable`, `OnDestroy`, `OnCollisionEnter2D`/`Stay2D`/`Exit2D` (with a `Collision2D`), `OnTriggerEnter2D`/`Stay2D`/`Exit2D` (with a `Collider2D`); `FixedUpdate`, `Update` and `LateUpdate` are called only on scripts whose type defines them with no parameters, public or not, declared on the type or a base type below `MonoBehaviour`, so a script without one costs nothing for it; `StartCoroutine`, `StopCoroutine` (given the `Coroutine`, or the `IEnumerator` the coroutine was started from: it stops each running coroutine of that script started from that object, does nothing when none is running, and throws `ArgumentNullException` for null; there is no string form), `StopAllCoroutines`; `useGUILayout` is stored. An exception a message throws is logged against the script. No other message is sent (`OnGUI`, `OnApplicationQuit`, `OnMouseDown`, `OnBecameVisible`, `OnValidate` and the 3D collision and trigger messages never run), and `Invoke`, `InvokeRepeating` and `CancelInvoke` are not defined. |
| `Transform` | `position`, `rotation`, `localPosition`, `localRotation`, `localScale`, `lossyScale`, `eulerAngles`, `localEulerAngles`, `right`, `up`, `forward`, `localToWorldMatrix`, `worldToLocalMatrix`, `parent`, `root`, `childCount`, `GetChild` (an index out of range throws `ArgumentOutOfRangeException`), enumeration of the children, `GetSiblingIndex`, `SetSiblingIndex`, `SetAsFirstSibling`, `SetAsLastSibling`, `DetachChildren`, `Find`, `IsChildOf`, `SetParent(parent)` and `SetParent(parent, worldPositionStays)` (under a parent whose scale makes its matrix singular the world pose cannot be kept, so the child keeps its local values as with `worldPositionStays` false; the engine's choice), `hasChanged`, `TransformPoint`, `InverseTransformPoint`, `TransformDirection`, `InverseTransformDirection`, `TransformVector`, `InverseTransformVector`, `Translate`, `Rotate`, `RotateAround`, `LookAt`, `SetPositionAndRotation`, `GetPositionAndRotation` and the local forms of the last two. `hasChanged` is set by scripts only; moves made by physics do not set it. |
| `ScriptableObject` | `name`, `CreateInstance<T>`, `CreateInstance(Type)` and `CreateInstance(string)`, with `Awake`, `OnEnable`, `OnDisable` and `OnDestroy`. An abstract or generic type throws `ArgumentException`; a class name that matches no type, or several, throws `InvalidOperationException`. |
| Attributes | `SerializeField`, `SerializeReference`, `Header`, `Range`, `CreateAssetMenu`, `RuntimeInitializeOnLoadMethod`, and the attribute classes in `UnityEngine` (`Tooltip`, `Space`, `Min`, `Multiline`, `TextArea`, `ColorUsage`, `Delayed`, `InspectorName`, `DisallowMultipleComponent`, `RequireComponent`, `AddComponentMenu`, `ContextMenu`, `ExecuteInEditMode`, `ExecuteAlways`, `HideInInspector`, `HelpURL`, `DefaultExecutionOrder`, `ExcludeFromPreset`, `SelectionBase`, `PreferBinarySerialization`, `AssetFileNameExtension`), `UnityEngine.Rendering` (`SupportedOnRenderPipeline` (`IsTypeSupportedOnRenderPipeline(type, pipeline)` is true for a type without the attribute and otherwise when the pipeline is a named type or derives from one, the engine's choice), `RecreatePipelineOnChange`, `ResourcePath`, `ResourcePaths`, `ResourceFormattedPaths`), `UnityEngine.Scripting` (`Preserve`, `AlwaysLinkAssembly`, `RequireImplementors`, `RequireAttributeUsages`), `UnityEngine.Scripting.APIUpdating` (`MovedFrom`) and `UnityEngine.Serialization` (`FormerlySerializedAs`). They are defined with their declared data so that scripts compile. The engine reads only `RequireComponent` in a running game, when `AddComponent` is called (see `GameObject`): `Range` limits nothing and `DefaultExecutionOrder` changes no order. A scene load binds public and `[SerializeField]` fields (see Loading scenes). `RuntimeInitializeOnLoadMethod` methods run when the host calls `RuntimeHooks` with the hooks listed in the player's manifest. |

Instantiated objects have their internal references remapped to the clone, as in Unity, and their `Awake` and `OnEnable` run before `Instantiate` returns. The clone's root is named after the original with a `(Clone)` suffix. Prefab assets are templates that take part in nothing until instantiated. `Destroy` follows Unity's timing: the object stops receiving update messages at once, but searches still find it and it compares non-null until the end of the frame, when `OnDisable` and `OnDestroy` run. `Destroy(component)` has the same timing for a script or native component: searches still find it and it compares non-null until the end of the frame, and a script's `OnDisable` and `OnDestroy` run in that frame's cleanup; destroying it twice does nothing. A component destroyed and replaced in one call leaves only the replacement. Destroying a `Transform` or `RectTransform` logs an error and changes nothing (the engine's choice; destroy the game object). `DestroyImmediate` on a component or game object takes effect for queries at once: the target (and a game object's descendants) drop out of `GetComponent`, `GetComponentsInChildren`, `FindObjectsByType`, `childCount` and `GetChild` and compare equal to null, and the queued `OnDisable` and `OnDestroy` messages run before it returns, including when called inside a message (the engine's choice; the same cleanup also runs the messages of anything else already destroyed in the frame). Native storage is still retired at the end of the frame.

## Loading scenes

A host loads a Unity scene from the plan `unity-import plan` writes, with `DisunityHost.LoadScene(planJson, new SceneLoadOptions(gameAssembly, fontBytes))`. The game's scripts are compiled into `gameAssembly` unchanged; `csharp/OriginalGames` shows a project that does this for a game checkout. `fontBytes` returns the TrueType bytes for a package font by name, such as Unity's `Arial`. The loader builds every object, engine component and script, sets serialized fields, registers the project's input axes, and then runs `Awake` and `OnEnable` for the scene together, as a Unity scene load does. Prefabs the scene references are kept as templates for `Instantiate` until the returned `LoadedScene` is disposed. If anything fails, the world is left as it was and `SceneLoadException` names the object, component or field.

Serialized fields bind as Unity deserializes them. Public and `[SerializeField]` fields are set; static, readonly and `[NonSerialized]` fields are not. A field the scene does not mention keeps its initializer, and scene data for a field the script no longer declares is ignored. Supported field types are numbers, `bool`, enums, `string`, `Vector2`, `Vector3`, `Vector4`, `Vector2Int`, `Vector3Int`, `Quaternion`, `Color`, `Color32`, `Rect`, `RectInt`, `Bounds`, `BoundsInt`, `Matrix4x4`, `LayerMask`, `RenderingLayerMask`, `AnimationCurve`, `Gradient`, references to objects, components, sprites, fonts and `ScriptableObject` assets, `UnityEvent` and `UnityEvent<T>` with up to four arguments, `[Serializable]` classes, arrays and `List<T>`. A `[SerializeReference]` field or list element holds the class the plan names (`{"$managed": {"class", "assembly", "fields"}}`), found in the named assembly, which must fit the declared type, be a non-abstract class and not be a `UnityEngine.Object`; a null reference loads as null. Any other type fails the load. A `[Serializable]` class that derives from a collection, such as a `Dictionary` subclass with serialized key and value lists, loads and is copied through its own serialized fields, as the engine's serializer treats it; a collection type with no serialized fields of its own, such as a bare `Dictionary` or `HashSet<T>`, fails the load. Every deserialized object, nested ones included, has `OnAfterDeserialize` called once its fields are set, innermost first, and `Object.Instantiate` calls `OnBeforeSerialize` on each nested source value and `OnAfterDeserialize` on its copy. A `[Serializable]` class with no parameterless constructor, public or not, is created without running any constructor, so its state is exactly its serialized data, and a field the data omits holds the type's default; a class with a parameterless constructor runs it and keeps its field initializers. `Object.Instantiate` copies serializable fields the same way. When a field cannot be read, the load error names the field and the innermost exception's type and message.

`LoadedScene.UnregisteredAxes` lists input axes that need a joystick or name a button the engine does not know; reading one fails as an unregistered axis does. `LoadedScene.Differences` lists authored presentation settings the engine does not reproduce, such as extrapolated bodies and camera shadow maps. `LoadedScene.Textures` gives the identity each scene texture's sprites use, for the host to upload.

## Time, input and coroutines

| Type | Supported |
| --- | --- |
| `Time` | `deltaTime`, `fixedDeltaTime` (read only), `time`, `frameCount`, `renderedFrameCount`, `unscaledDeltaTime`, `unscaledTime`, `smoothDeltaTime`, `timeScale` (0 to 100; a value outside the range is clamped with a warning and NaN throws `ArgumentOutOfRangeException`), `maximumDeltaTime` (a non-finite value throws `ArgumentOutOfRangeException`), `realtimeSinceStartup`, `realtimeSinceStartupAsDouble`. The native world owns the clock, so every value includes the time scale and the maximum frame length. |
| `Input` | `GetKey`, `GetKeyDown`, `GetKeyUp`; `GetAxis` (smoothed) and `GetAxisRaw` for any axis the host registered; `GetButton`, `GetButtonDown` and `GetButtonUp`, which read the keys of a registered axis; `anyKey`, `anyKeyDown`. The mouse is present and idle: `mousePresent` is true, `mousePosition` and `mouseScrollDelta` are zero, and `GetMouseButton`, `GetMouseButtonDown` and `GetMouseButtonUp` return false (a negative button throws `ArgumentOutOfRangeException`). There are no touches: `touchSupported` is false, `touchCount` is 0, `touches` is empty and `GetTouch` throws `ArgumentOutOfRangeException`. `compositionString` is empty, and `imeCompositionMode` and `compositionCursorPos` are stored. `Touch` is a data struct. |
| `KeyCode` | Keyboard, mouse and joystick members with the standard numeric values (`Backspace` 8, `Return` 13, `Escape` 27, `Space` 32, `Alpha0` to `Alpha9` 48 to 57, `A` to `Z` 97 to 122, `Delete` 127, `Keypad0` 256, `UpArrow` 273, `F1` to `F15` 282 to 296, `LeftShift` 304, `Mouse0` 323, `JoystickButton0` 330, `Joystick1Button0` 350 through `Joystick8Button19` 509), the punctuation members, and the aliases `RightApple` and `LeftApple` for the Command keys. A game's compiled key constants and `Enum.Parse<KeyCode>` of a key name read the member they name. The desktop host delivers letters, digits, `F1` to `F12`, the arrows, editing keys, modifiers and punctuation; it reports a modifier without its side, so `Shift`, `Control` and `Alt` press the left key (the engine's choice). Keypad, mouse and joystick buttons are never pressed, and `anyKey` scans only the keys the host delivers. |
| `UnityEngine.InputSystem.Keyboard` | `Keyboard.current.aKey` and `dKey` with `isPressed` |
| Yield instructions | `WaitForSeconds`, `WaitForSecondsRealtime`, `WaitForFixedUpdate`, `WaitForEndOfFrame`, `null` (next frame), nested `IEnumerator`, a `CustomYieldInstruction` subclass (checked once a frame), an `AsyncOperation` (the coroutine resumes in the first frame after it is done). Yielding anything else, including a `Coroutine`, throws `NotSupportedException`. |

No axes exist until the host registers them with `DisunityHost.RegisterInputAxis`, giving each a name, negative and positive keys, alternate keys, gravity, sensitivity, dead zone, snap and invert, as in Unity's Input Manager. Asking for an unregistered axis throws `ArgumentException`. A scene plan or a player's resource plan registers its axes at load: a mouse movement axis such as `Mouse X` registers with no keys and reads 0, because the engine's mouse never moves, while a joystick axis, or a key axis that names a button the engine does not know (a misspelling, `joystick 9 button 0`), stays unregistered and is logged. A button name registers for every key the engine defines: `backspace`, `tab`, `return`, `enter` (the keypad Enter), `escape`, `space`, `delete`, `insert`, `home`, `end`, `page up`, `page down`, `up`, `down`, `left`, `right`, `left shift`, `right shift`, `left ctrl`, `right ctrl`, `left alt`, `right alt`, `left cmd`, `right cmd`, `f1` to `f15`, `0` to `9`, `a` to `z`, the keypad `[0]` to `[9]`, `[+]`, `[-]`, `[*]`, `[/]`, `[.]` and `[=]`, `equals`, the punctuation marks, `mouse 0` to `mouse 6`, `joystick button 0` to `joystick button 19` and `joystick K button N` for K 1 to 8. A button the machine may have but nothing here presses (a mouse or joystick button, since no joystick is attached) registers and reads never pressed, as mouse movement reads zero (the engine's choice). A player takes its axes from the `InputManager` of `globalgamemanagers`; the Old World player lists 20, among them `Horizontal`, `Vertical`, `Mouse X`, `Mouse Y`, `Mouse ScrollWheel`, `Submit` and `Cancel`. Gamepads and Input System actions are not implemented, and the mouse and touch members are idle as the `Input` row describes. A coroutine that yields `WaitForEndOfFrame` resumes once, after every `LateUpdate` of the frame; one that yields it while resuming from that point waits for the end of the next frame.

## Player settings and scenes

| Type | Supported |
| --- | --- |
| `QualitySettings` | `antiAliasing`, `globalTextureMipmapLimit`, `maximumLODLevel`, `maxQueuedFrames`, `vSyncCount`, `lodBias`, `enableLODCrossFade`, `shadowDistance`, `shadows`, `activeColorSpace`, `names`, `GetQualityLevel` and `SetQualityLevel`. The state is the engine's own and resets when a world loads: one level named "Default", anti-aliasing 0, vertical sync 1, LOD bias 1, LOD cross-fade on, shadow distance 150, gamma. The engine does not know a project's per-level values yet, so switching levels changes only the current index. `SetQualityLevel` with an index at or above the level count selects the last level (the original Old World player calls it with 3 and defines three levels, and runs on); a negative index throws `ArgumentOutOfRangeException`. The setters also throw `ArgumentOutOfRangeException` for `antiAliasing` other than 0, 2, 4 or 8, a negative `globalTextureMipmapLimit` or `maximumLODLevel`, `maxQueuedFrames` outside 1 to 10, `vSyncCount` outside 0 to 4, a `lodBias` that is not finite and positive, a negative or NaN `shadowDistance`, and an undefined `shadows`. Each level can hold a render pipeline asset: `GetRenderPipelineAssetAt(index)` reads one (an index outside the levels throws `ArgumentOutOfRangeException`) and `renderPipeline` reads and replaces the current level's. Levels start without assets, and a loading world clears them. Hosts supply levels and color space with `DisunityHost.SetQualityLevels` and `SetColorSpace`; a player's start gives each level its asset with `DisunityHost.ApplyRenderPipelines`. |
| `SceneManager` | `GetActiveScene`, `SetActiveScene`, `sceneCount`, `GetSceneAt`, `sceneCountInBuildSettings`, the `sceneLoaded`, `sceneUnloaded` and `activeSceneChanged` events, and `LoadScene` and `LoadSceneAsync` by name or build index, in `Single` or `Additive` mode. A scene is found by its name (the file name without `.unity`), its path, or its path without `Assets/` and `.unity`. A player's build is the scene list in the play request; a project run has one scene, its plan, and loading any other throws `ArgumentException` naming it. A load takes effect in the delayed-tasks phase of the frame that is running or next runs (the engine's choice). A `Single` load raises `sceneUnloaded` for each loaded scene and destroys its roots through `Destroy` except those marked `DontDestroyOnLoad` (so `OnDisable` and `OnDestroy` run), the new plan loads and its scripts wake, then `sceneLoaded` and `activeSceneChanged` are raised. An `Additive` load adds the scene beside the loaded ones and raises only `sceneLoaded`; the active scene stays. `sceneCount` and `GetSceneAt` list the loaded scenes in load order. `SetActiveScene` makes a loaded scene active and raises `activeSceneChanged` when it changes. Objects created at run time join the active scene; an additive scene owns the roots its load created. `sceneLoaded` is raised once the scene's objects have received `Awake` and `OnEnable`, before any `Start`; during `Awake` the old scene is still the active scene. A scene whose plan failed to build throws `InvalidOperationException` naming the scene and the planning error. An undefined `LoadSceneMode` throws `ArgumentOutOfRangeException`. There is no `UnloadSceneAsync`. A scene script whose class cannot load, because it uses an engine type the engine does not define, is left off its object like a missing script: the scene still loads, a warning is logged and the plan's differences name it. Any other failure while a scene loads throws `SceneLoadException` naming the object and component, the exception and each inner exception. |
| `SceneUtility` | `GetScenePathByBuildIndex` (empty for an index outside the build) and `GetBuildIndexByScenePath` (-1 for a path outside the build). |
| `Scene` | `name`, `path`, `buildIndex`, `handle` (a `SceneHandle`), `isLoaded`, `IsValid`, `rootCount` and `GetRootGameObjects`. Each load gets a new handle. Roots marked `DontDestroyOnLoad` and their children belong to no scene (`GameObject.scene` is the invalid scene), where the engine's choice differs from a separate "DontDestroyOnLoad" scene. |
| `SceneHandle` | The value `Scene.handle` returns: a struct over the engine's scene id with `==`, `!=`, `Equals`, `GetHashCode`, `CompareTo` (by raw value), `ToString` (the raw value), `GetRawData`, `FromRawData` and implicit conversions to and from `int` (the scene id; the default handle is 0). The default handle is the invalid scene's. The raw value is the scene id as an unsigned number (the engine's choice). |
| `RectOffset` | `left`, `right`, `top`, `bottom`, `horizontal`, `vertical`, `Add` (grows a `Rect` outwards), `Remove` (shrinks it inwards) and `ToString`. Values may be negative. |
| `SecondarySpriteTexture` | `name` and `texture`. `Sprite.GetSecondaryTextureCount` returns 0 and `Sprite.GetSecondaryTextures` copies none, since sprites the engine builds carry no secondary textures. |
| `UISystemProfilerApi` | `BeginSample`, `EndSample` and `AddMarker`, and `SampleType`. The engine has no profiler capture, so markers are accepted and dropped. |
| `TouchScreenKeyboard`, `RangeInt` | The type exists so UI scripts load. The engine has no on-screen keyboard: `isSupported`, `isInPlaceEditingAllowed` and `visible` are false, `area` is empty and `hideInput` is stored. Every `Open` overload throws `NotSupportedException` (the engine's choice, since callers check `isSupported`), so no instance exists and the instance members (`text`, `active`, `status`, `characterLimit`, `canGetSelection`, `canSetSelection`, `selection`, `type`, `targetDisplay`) throw `NotSupportedException`. `TouchScreenKeyboard.Status` is `Visible`, `Done`, `Canceled` and `LostFocus`. `RangeInt` holds `start`, `length` and `end`. |
| `Canvas.GetDefaultCanvasMaterial`, `Canvas.GetETC1SupportedCanvasMaterial` | Static. Return one shared `Material` named "Default UI Material" on the shader `UI/Default`, which the engine registers with render queue 3000 (transparent) and one pass (the engine's choice). The material is created on first use; if a game destroys it the next call makes a new one. The ETC1 form returns the same material, since the engine has no split colour and alpha textures. Nothing draws with it yet. |
| `UnityEngine.Sprites.DataUtility` | Static. `GetOuterUV` is the sprite's `textureRect` divided by its texture size and `GetInnerUV` is that rectangle inset by the border (where the sprite's rectangle has padding around its pixels, the padding counts toward the border), both as (xMin, yMin, xMax, yMax). `GetPadding` is the offset of the pixels inside `rect` as (left, bottom, right, top), zero for a tight sprite. `GetMinSize` is (left + right, bottom + top) of the border. A sprite with no managed texture, such as a sprite of the scene, gets the unit UV (0, 0, 1, 1) for both UVs and zero padding (the engine's choice). A null sprite throws `ArgumentNullException`. |
| `Event` | The immediate-mode GUI event record: `type`, `rawType`, `mousePosition`, `delta`, `button`, `clickCount`, `modifiers` (with `shift`, `control`, `alt`, `command`, `capsLock`, `numeric` and `functionKey`), `pressure`, `keyCode`, `character`, `commandName`, `displayIndex`, `isKey`, `isMouse`, `isScrollWheel`, `Use`, `GetTypeForControl`, the copy constructor, `Equals` and `ToString`. The engine draws no OnGUI layer, so `Event.current` is null, `Event.PopEvent` returns false and leaves its argument alone, and `Event.GetEventCount` is 0. After `Use`, `type` reads `Used` and `rawType` keeps the earlier type (the engine's choice); setting `type` clears the use. `Event.KeyboardEvent` throws `NotSupportedException`. `keyCode` is the engine's `KeyCode`. |
| `MissingComponentException` | The exception type, with the usual constructors. |
| `ICanvasRaycastFilter` | The interface, so UI scripts that implement it load. The engine sends no UI pointer events yet, so nothing calls it. |
| `AsyncOperation` | `isDone`, `progress`, `priority`, `allowSceneActivation` and `completed`. A `LoadSceneAsync` operation has progress 0 until the load happens and 1 after it. With `allowSceneActivation` false it reports 0.9 and waits; setting it true loads at the next frame's delayed-tasks phase. A coroutine that yields the operation resumes in the first frame after it is done; the native scheduler owns that resumption. `ResourceRequest` (from `Resources.LoadAsync`) and `AsyncInstantiateOperation` derive from it. |
| `Cursor` | `visible`, `lockState` and `SetCursor`. `SetCursor` stores the texture, hotspot and mode, and a null texture restores the default cursor; the engine draws no cursor image. The play window does not apply the state yet; a presentation host reads `DisunityHost.CursorVisible`, `CursorLockState`, `CursorTexture`, `CursorHotspot` and `CursorMode`. |
| `UIElements.PanelInputConfiguration` | A `MonoBehaviour` with `settings` (`PanelInputConfiguration.Settings`, data fields with `Settings.Default`: `AutoSwitch` redirection, world space input on, every layer, unlimited distance, panel components created automatically) and `PanelInputRedirection`. A world has no UI Toolkit panels, so the static `current` is null and an event system drives uGUI only. An undefined redirection throws `ArgumentOutOfRangeException`. |
| `Screen` | `width`, `height`, `dpi`, `currentResolution`, `resolutions`, `mainWindowDisplayInfo`, `GetDisplayLayout`, `safeArea` (the whole screen), `cutouts` (empty) and `mainWindowPosition` (zero) describe the one display the window fills. An interpolated body is drawn between its poses before and after the last physics step, by the fraction of a step the clock has run past it, so it moves smoothly when frames and physics steps do not line up. As in Unity it is drawn up to one step behind physics. Unlike Unity, its `transform` keeps the physics pose: interpolation changes what is drawn, and scripts, contacts and queries all see the step pose. A body moved by a script since the last step is drawn where it is.

Physics uses continuous collision detection for all 2D bodies. Joints, effectors, polygon and edge colliders in C#, and 2D forces and impulses (`Rigidbody2D.AddForce`) are not defined, so code that uses them does not compile. 3D physics is described in the next section.

The mesh keeps no skin weights, so the blend channels are never sent. `MeshCollider.sharedMesh` and `BatchRendererGroup.RegisterMesh` only hold the reference. Channels: `vertices`, `normals`, `tangents`, `colors`, `colors32`, and `uv` to `uv8` (uv channels 0 to 7), with array and `List` forms `SetVertices`, `SetNormals`, `SetTangents`, `SetColors` (`Color` and `Color32`), `SetUVs` (`Vector2`, `Vector3`, `Vector4`) and the matching `Get...` that clear the list first. A uv channel remembers the component count of its last set (2, 3 or 4): reading with more components pads zeros and reading with fewer drops the rest. A channel is empty or as long as `vertexCount`, so a set with another length throws `ArgumentException` naming the channel, and the positions are set first. Setting `vertices` to a different count drops the other channels that no longer fit, and throws `InvalidOperationException` naming the sub-mesh if an index would fall outside the new count. Sub-meshes: a new mesh has one empty triangle sub-mesh. `subMeshCount` grows with empty sub-meshes or truncates. `SetTriangles` (array and `List`, with `calculateBounds` and `baseVertex` overloads) and `SetIndices` (with a `MeshTopology`) need whole primitives (3 for Triangles, 4 for Quads, 2 for Lines, 2 or more or none for LineStrip) and every index plus the base vertex inside `[0, vertexCount)`, otherwise `ArgumentException`; a sub-mesh outside `[0, subMeshCount)`, including `subMeshCount` itself, throws `ArgumentOutOfRangeException`. `triangles` returns every sub-mesh joined with base vertices applied (it throws `InvalidOperationException` when a sub-mesh is not a triangle list), and setting it replaces all sub-meshes with one. `GetIndices`, `GetTriangles`, `GetIndexStart` (the sum of earlier index counts), `GetIndexCount`, `GetBaseVertex` (all three return `uint`, as compiled game code expects; a negative base vertex reads as its two's complement) and `GetTopology` read them back; `GetIndices` and `GetTriangles` apply the base vertex unless told not to. `indexFormat` is `UInt16` by default, and with it an index above 65535 throws `ArgumentException` instead of being truncated. `bounds` is set explicitly, by `RecalculateBounds` (the box around every position; zero for an empty mesh), or by the `triangles` setter and by `SetTriangles` and `SetIndices` unless `calculateBounds` is false; setting `vertices` leaves it alone. `RecalculateNormals` area-weights the faces around each vertex by index, ignores sub-meshes that are not triangle lists and gives a vertex without a triangle (0, 0, 0); a quad in the XY plane wound clockwise as seen from -z gets normal (0, 0, -1). `RecalculateTangents` needs normals and `uv` (else `InvalidOperationException` naming what is missing) and gives each vertex the direction in which u grows, orthogonal to its normal, with w = -1 or 1 for the handedness; a vertex without usable uvs gets an arbitrary perpendicular and w = 1. `Clear()` and `Clear(bool)` empty everything (one empty sub-mesh remains) and zero the bounds. `UploadMeshData(true)` makes the mesh unreadable: reading or writing data throws `InvalidOperationException` ("mesh is not readable"), while `bounds`, `vertexCount`, `subMeshCount`, `indexFormat`, `GetIndexStart`, `GetIndexCount`, `GetBaseVertex` and `GetTopology` keep working. `Optimize`, `OptimizeIndexBuffers`, `OptimizeReorderVertexBuffer` and `MarkDynamic` leave the data as it is. A Mesh asset of a player's resource plan builds as a readable mesh (the engine's choice: the player keeps every mesh readable) with the planned name, positions, normals, tangents, colors, uv channels, sub-meshes (topology and base vertex), `indexFormat` and `bounds`; `Resources.Load<Mesh>` and every `MeshFilter` that names the mesh return the one object. |

## Reading offscreen graphics from a host

A host that draws what scripts record reads one `GraphicsSnapshot` (`worldrunner_world_simulation::graphics`) for each frame. It holds the offscreen work in call order (`Camera.Render` into a render texture, `Graphics.Blit`, `Graphics.CopyTexture` and `ComputeShader.Dispatch`), the cameras those renders name with their settings and pose, the mesh renderers those cameras may draw, the materials and shaders of the blits and renderers, every live render texture, the global shader state, and the compute shaders and compute buffers (contents included) that the dispatches name. A texture a dispatch took from the global shader state is already resolved in its record.

- A host whose world is in its own process calls `GraphicsSnapshot::take(&mut World)`.
- A host that loads the engine image calls `DisunityHost::graphics_snapshot()`, and a GPU flush handler calls `GpuFlush::snapshot()`. Both drain the pending work, so a second call returns only work recorded after the first, and a frame with no work gives an empty snapshot.
- Across the ABI the call is `disunity_graphics_snapshot(world, buffer, capacity, length)`. The image encodes the snapshot with `graphics::snapshot_wire::encode` (a marker, a version and a length, then every field, floats bit for bit) and the host decodes it with `decode`, which refuses truncated or corrupt bytes, another version and any length over its cap with a named `WireError`. A call with a zero `capacity` reports the length and takes the work into the image; the call that copies hands the bytes out. A `capacity` that is too small fails and loses nothing, and work recorded between the two calls comes with the next snapshot. A snapshot nobody copied is dropped when the world advances.

A loaded asset stays loaded for the world's lifetime, so `UnloadAsset` only checks its argument (null throws `ArgumentNullException`) and unloads nothing, and `UnloadUnusedAssets` completes on the next frame. `LoadAsync` completes on the next frame, and reading `ResourceRequest.asset` earlier loads at once. `FindObjectsOfTypeAll` lists the scene's game objects and components, inactive ones included, and throws `NotSupportedException` for `Object` or any type that could include an asset. `GetBuiltinResource` throws `NotSupportedException`, since the engine has no built-in resources. |
| `TextAsset` | `text`, `bytes`, `dataSize`, `ToString`, and `new TextAsset(string)`. `text` decodes a UTF-32, UTF-8 or UTF-16 byte order mark and otherwise reads UTF-8. |
| `InstantiateAsync`, `AsyncInstantiateOperation`, `InstantiateParameters` | `Object.InstantiateAsync` with a count, parent, positions and rotations, or `InstantiateParameters`. The clones are made on the main thread in the first frame after the call (at once when no world is loaded). `isDone`, `completed`, `Result`, `WaitForCompletion` (makes the clones at once), `Cancel` and `await` work. If making the clones fails, the exception is logged and `Result` stays null. A world-space clone under a parent and a valid `scene` throw `NotSupportedException`; positions and rotations with a different length from the count throw `ArgumentException`. |
| `AssetBundle` | The type exists. `LoadFromFile` and every instance member (`LoadAsset`, `LoadAssetWithSubAssets`, `LoadAllAssets`, `GetAllAssetNames`, `Unload`) throw `NotSupportedException`: asset bundles are not loaded yet. |
| `UnityEngine.Networking.UnityWebRequest` | The request object model: `UnityWebRequest(url, method)`, `Get`, `EscapeURL` (form encoding, a space becomes `+`), `uri`, `method`, `SetRequestHeader`, `downloadHandler`, `uploadHandler`, `Dispose`, and before any send `isDone` (false), `responseCode` (0), `result` (`InProgress`) and `GetResponseHeaders()` (null). | `DownloadHandler`, `DownloadHandlerBuffer`, `DownloadHandlerTexture`, `UnityWebRequestTexture` | `data`, `text` and `texture` are null because no content arrives. `DownloadHandler` has a `protected virtual CompleteContent()` that does nothing. `UnityWebRequestTexture.GetTexture` returns a GET request with a texture handler. |
| `UploadHandler`, `UploadHandlerRaw` | `UploadHandlerRaw(bytes)` keeps a copy of the bytes in `data`; `contentType` starts null and can be set. |
| `JsonUtility` | `ToJson(object)` and `FromJson<T>(string)`. Both use the fields a scene load binds: public and `[SerializeField]` instance fields, not `readonly` or `[NonSerialized]`. The JSON is compact, base class fields first. Numbers, `bool`, `string` (null as `""`), enums (as integers), arrays and `List<T>` (null as `[]`), nested classes and structs, `Vector2`, `Vector3`, `Vector4`, `Quaternion` and `Color` are supported. | `UnityEngine.Rendering.CommandBuffer` | `name` (starts empty; null becomes empty), `Clear`, `Release` and `Dispose`. After `Release` every member except `name` and `Release` throws `ObjectDisposedException`. | `Unity.Baselib.LowLevel.Binding` | The platform layer Unity Transport calls. Page memory: `Baselib_Memory_GetPageSizeInfo` (the system page size), `AllocatePages` (aligned to the requested multiple of the page size and zeroed; a page size that is not a power of two or no pages fails), `ReleasePages` and `SetPageState` (accepted; pages stay readable and writable). Timers: high-resolution ticks, their nanosecond ratio, time since startup and `WaitForAtLeast`. | `Unity.TLS.LowLevel.Binding` | The data types and the client callback delegates Unity Transport loads. No TLS function is implemented, so a secured connection fails naming the first one it calls. |
| `ComputeBuffer` | The constructors `(count, stride)`, `(count, stride, type)` and `(count, stride, type, mode)` (a count or stride of zero or less throws `ArgumentException`), `count`, `stride`, `IsValid`, `Release` and `Dispose` (the same operation, repeatable; `count` and `stride` still read afterwards). The world holds the contents from the first use and checks the shape then: a stride that is a multiple of 4 from 4 to 2048, at most 256 MiB, otherwise `ArgumentException`. `SetData` takes an array, a `List<T>` or a `NativeArray<T>`, each with or without a managed start, buffer start and count, and writes the elements' bytes; `GetData` takes an array with or without those offsets, runs the host's GPU flush first and then copies the bytes out. A flush handler that fails does not fail `GetData`: the engine logs the handler's reason once per distinct reason and `GetData` returns what the CPU holds. Without a handler `GetData` returns what the CPU wrote, zeros for the rest. The element type of an array need not match the stride (the engine's choice is that the stride only sizes the buffer): offsets and counts are in elements of the array's type, and the byte range they name has to fit the buffer, so a buffer of one 20 byte element takes five unsigned integers. A range outside the array, a byte range past the end of the buffer, or an element type without a fixed size throws `ArgumentException` or `ArgumentOutOfRangeException`, and any contents call after `Release` throws `ObjectDisposedException`. |
