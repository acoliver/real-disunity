## Resolution protocol for later reviewers

Initial authoring and the Stage 2 training-only review leave every entry unresolved. In a later separately authorized verification review, attach evidence to the stable ID rather than silently deleting the concern. Record exact Unity editor/player revision, package versions, operating system, scripting backend, graphics/audio/network backend where relevant, and whether the finding is a declaration check, behavioral experiment, format inspection, or inference. A successful compilation resolves only the compiled declaration; it does not prove runtime semantics.

Suggested finding fields are `uncertainty_id`, `topic_ids`, `status`, `environment`, `claim_checked`, `observation`, `evidence_kind`, `remaining_gap`, and `proposed_correction`. Independent reviewers should identify disagreements rather than treating one another's edits as primary evidence. An entry can be partially resolved without making the whole group verified.

No global fraction of Unity's API is estimated. The 18 groups and 108 topics are a bounded authoring inventory, and the depth labels are only self-assessment of this artifact's treatment.
