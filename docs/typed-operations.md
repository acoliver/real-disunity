# Typed operations in authored order

`contracts::ResourceRegistry::compile_operations` compiles one list of `TypedOperation` values. Raster passes, fullscreen triangles, compute dispatches, buffer uploads, texture and buffer copies, and readbacks execute in exactly that order. Raster work uses the existing `RasterPass` attachments and validator. Compute declares workgroup counts and checked groups containing sampled or storage textures, uniform buffers and storage buffers. No callback receives a command encoder or queue through this API. The raster draw callback retains the existing render-pass interface.

Each operation has a semantic `RasterId`, consisting of a `StageId` and authored occurrence. IDs must be unique within the list. `CompiledOperations::encode` accepts an optional `PassTimer`; results use `PassId::Operation` with that identity. Render and compute timestamps use pass boundaries. Copies and uploads use empty compute passes around the transfer when timing is enabled, avoiding a requirement for encoder timestamp support. Existing stock stage identities and stock execution remain unchanged.

## Buffer identity and checked bindings

`import_buffer`, `replace_buffer` and `buffer_view` give buffers the same physical identity, generation, lifetime and logical-version rules as textures. A clone cannot acquire another identity in the same registry. Replacement invalidates old ranges and removes initialized contents. Read-only imports reject writes and replacement. Buffer uses declare byte intervals, access, usage and prior versions. Overlapping writable intervals in one operation fail, while disjoint intervals may be used independently only when their whole-buffer GPU usages are compatible. Writable storage cannot share a pass with uniform, read-only storage, vertex or index usage of the same allocation, even at disjoint offsets. Multiple disjoint writable-storage bindings remain legal. Copies within one backing buffer are rejected because WebGPU forbids them, even when the intervals are disjoint.

`CheckedBindings::build_with_buffers` creates the actual layout and group from texture entries and `BufferBinding` values. Each buffer entry has a base byte interval and an optional dynamic offset. The offset shifts both ends of the interval. Base alignment, offset alignment, binding size, effective bounds, usage and device binding limits are checked before group creation. Dynamic offsets are installed in binding-number order. Declare the effective interval, version and access in `TypedOperation::buffers`; declaring only the unshifted interval fails validation. Read-write storage consumes the prior version supplied by its `BufferUse` declaration.

The raster-only `compile` entry point rejects buffer groups because it has no buffer declarations. Use the mixed-operation entry point for raster or fullscreen passes with buffer groups. Pipelines remain caller-created with layouts from the checked groups, as with the existing raster API. Shader and pipeline compatibility are validated by wgpu at creation and encoding; resource declarations do not reflect shader arithmetic or replace those checks.

## Transfers and subresources

`view_dimension` creates actual D2, D2Array, Cube and CubeArray views. Cube views require six square layers; cube arrays require a multiple of six. Copies address a single mip and the selected layer range, including cube faces and nonzero mips. Copy origins are relative to the selected mip's XY extent; the Z origin comes from the selected layers. Copies retain block alignment and bounds checks. Texture-to-buffer and buffer-to-texture operations declare byte offsets, row pitch and rows per image, with aligned encoder-copy pitches and sufficient destination or source capacity.

`TextureCopy::whole` selects the physical, block-rounded mip extent. Compressed copy extents must be block multiples, including mips smaller than one block. Depth/stencil copies require full XY extents; buffer transfers also enforce direction-specific aspect restrictions. Buffer versions cover only copied rows, preserving row padding, image gaps and unused capacity. Partial destination rectangles require `before` and fully initialized prior subresources. Validity remains conservative at mip/layer/aspect granularity; the compiler does not infer initialization of individual rectangles. Buffer uploads freeze their bytes in immutable staging only after the complete list validates. Encoding copies that staging at the authored position, so scratch-uniform updates can occur between dependent dispatches or draws in one submission. There are no queue writes or implicit hoisting.

Readback variants require caller-owned MAP_READ staging registered as writable buffers. Submit the encoded commands before `AsyncReadback::begin`. The host drives `device.poll(Poll)` and calls `try_read`, which returns immediately with either no completion, native bytes or a typed mapping error. Dropping an unfinished reader unmaps without waiting. A caller must not map the same staging buffer twice, reuse it while mapped, or drop its submission ownership prematurely.

Compilation checks the whole recipe before staging allocation. Encoding checks every referenced generation before recording commands. As with raster compilation, version state is local to one compiled list; submission ownership, cross-frame publication, retirement and cancellation are separate contracts. Supplied cascade matrices remain sufficient for shadow casters. Generic caster collection is deferred.
