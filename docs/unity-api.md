# Supported UnityEngine API

`Disunity.Engine` implements a subset of the `UnityEngine` API. This page lists the types and members the assembly defines, grouped the way a game uses them, and says what each one does. A member described as stored or defined keeps its value and has no effect on the simulation or on a frame. A member that cannot work throws an exception, and the row names it: usually `NotSupportedException` with the member's name in the message, or `DisunityException` when the native world rejects a value. A type or member this page does not list is not covered here; read its source before relying on it.

The source of truth is `csharp/Disunity`. Each type lives in a file of the same name, so `csharp/Disunity/Physics2D.cs` holds `Rigidbody2D` and the 2D colliders. Writing scripts and hosting them is covered in [Writing C# scripts](csharp-games.md).

## Objects, components and lifecycle

These cover creating, finding and destroying things, which nearly every script uses.

Destroying a single component throws `NotSupportedException`.

## Loading scenes

A host loads a Unity scene from the plan `unity-import plan` writes, with `DisunityHost.LoadScene(planJson, new SceneLoadOptions(gameAssembly, fontBytes))`. The game's scripts are compiled into `gameAssembly` unchanged; `csharp/OriginalGames` shows a project that does this for a game checkout. `fontBytes` returns the TrueType bytes for a package font by name, such as Unity's `Arial`. The loader builds every object, engine component and script, sets serialized fields, registers the project's input axes, and then runs `Awake` and `OnEnable` for the scene together, as a Unity scene load does. Prefabs the scene references are kept as templates for `Instantiate` until the returned `LoadedScene` is disposed. If anything fails, the world is left as it was and `SceneLoadException` names the object, component or field.

Serialized fields bind as Unity deserializes them. Public and `[SerializeField]` fields are set; static, readonly and `[NonSerialized]` fields are not. A field the scene does not mention keeps its initializer, and scene data for a field the script no longer declares is ignored. Supported field types are numbers, `bool`, enums, `string`, `Vector2`, `Vector3`, `Vector4`, `Vector2Int`, `Vector3Int`, `Quaternion`, `Color`, `Color32`, `Rect`, `RectInt`, `Bounds`, `BoundsInt`, `Matrix4x4`, `LayerMask`, `RenderingLayerMask`, `AnimationCurve`, `Gradient`, references to objects, components, sprites, fonts and `ScriptableObject` assets, `UnityEvent` and `UnityEvent<T>` with up to four arguments, `[Serializable]` classes, arrays and `List<T>`. A `[SerializeReference]` field or list element holds the class the plan names (`{"$managed": {"class", "assembly", "fields"}}`), found in the named assembly, which must fit the declared type, be a non-abstract class and not be a `UnityEngine.Object`; a null reference loads as null. Any other type fails the load. A `[Serializable]` class that derives from a collection, such as a `Dictionary` subclass with serialized key and value lists, loads and is copied through its own serialized fields, as the engine's serializer treats it; a collection type with no serialized fields of its own, such as a bare `Dictionary` or `HashSet<T>`, fails the load. Every deserialized object, nested ones included, has `OnAfterDeserialize` called once its fields are set, innermost first, and `Object.Instantiate` calls `OnBeforeSerialize` on each nested source value and `OnAfterDeserialize` on its copy. A `[Serializable]` class with no parameterless constructor, public or not, is created without running any constructor, so its state is exactly its serialized data, and a field the data omits holds the type's default; a class with a parameterless constructor runs it and keeps its field initializers. `Object.Instantiate` copies serializable fields the same way. When a field cannot be read, the load error names the field and the innermost exception's type and message.

`LoadedScene.UnregisteredAxes` lists input axes that need mouse, joystick or keys the engine does not deliver; reading one fails as an unregistered axis does. `LoadedScene.Differences` lists authored presentation settings the engine does not reproduce, such as extrapolated bodies and camera shadow maps. `LoadedScene.Textures` gives the identity each scene texture's sprites use, for the host to upload.

| Type | Supported |

No axes exist until the host registers them with `DisunityHost.RegisterInputAxis`, giving each a name, negative and positive keys, alternate keys, gravity, sensitivity, dead zone, snap and invert, as in Unity's Input Manager. ## 2D physics

| Type | Supported |
| --- | --- |
| `Rigidbody2D` | `bodyType` (Dynamic, Kinematic, Static), `velocity`, `linearVelocity`, `angularVelocity`, `mass`, `gravityScale`, `freezeRotation`, `constraints` (`RigidbodyConstraints2D` freeze position X, Y and rotation), `simulated`, `position`, `MovePosition`, `Sleep`, `WakeUp`, `IsSleeping`, `sharedMaterial`, `interpolation` (None and Interpolate; Extrapolate throws `NotSupportedException`) |
| `Collider2D` | `enabled`, `isTrigger`, `offset`, `attachedRigidbody`, `sharedMaterial`. |
| `BoxCollider2D`, `CircleCollider2D` | `size`; `radius` |
| `UnityEngine.Tilemaps.TilemapCollider2D` | Collides with the `Tilemap` on its object, following its cells as they change. Contacts and queries return it like any other collider. |
| `UnityEngine.Tilemaps.Tilemap` | `enabled`, `color`, `tileAnchor`. The host sets the grid layout, tile palette and cells with `DisunityHost.ConfigureTilemap`, `SetTile` and `SetCells`, and the `TilemapRenderer` material with `DisunityHost.SetTilemapMaterial` (read with `TilemapMaterial`). With `Material.SpriteLit` the tiles take the scene's global 2D lights on their sorting layer, as lit sprites do. The script `Tile` and `Grid` APIs are not implemented. |
| `PhysicsMaterial2D` | `name`, `friction`, `bounciness` |
| `Collision2D` | `collider`, `otherCollider`, `gameObject`, `transform`, `rigidbody`, `contacts`, `contactCount`, `GetContact`. A collision carries one contact; `GetContact` with any other index throws `ArgumentOutOfRangeException`. `ContactPoint2D` has `point` and `normal`. |
| `Physics2D` | `Raycast(origin, direction, distance, layerMask)` (nearest hit), `OverlapCircle(point, radius, layerMask)` (first hit, or null). No other `Physics2D` member is defined. |
| `RaycastHit2D` | `collider`, `point`, `normal`, `distance`, conversion to `bool`. It has no `transform` or `rigidbody`. |

An interpolated body is drawn between its poses before and after the last physics step, by the fraction of a step the clock has run past it, so it moves smoothly when frames and physics steps do not line up. As in Unity it is drawn up to one step behind physics. Unlike Unity, its `transform` keeps the physics pose: interpolation changes what is drawn, and scripts, contacts and queries all see the step pose. A body moved by a script since the last step is drawn where it is.

Physics uses continuous collision detection for all 2D bodies. Joints, effectors, polygon and edge colliders in C#, and 2D forces and impulses (`Rigidbody2D.AddForce`) are not defined, so code that uses them does not compile. 3D physics is described in the next section.

## 3D physics

The engine has no 3D simulation. The 3D types are defined so that scripts that mention them compile, and they behave as an empty 3D world.

| Type | Supported |
| --- | --- |
| `Rigidbody` | `AddComponent<Rigidbody>` throws `NotSupportedException`, so no rigidbody is simulated. An instance made with `new` stores its values with Unity's defaults and reads them back: `linearVelocity` (and `velocity`), `angularVelocity`, `linearDamping` (`drag`), `angularDamping` (`angularDrag`), `mass`, `useGravity`, `isKinematic`, `constraints`, `freezeRotation`, `collisionDetectionMode`, `interpolation`, `centerOfMass`, `inertiaTensor`, `inertiaTensorRotation`, `position`, `rotation`, `detectCollisions`, the solver, sleep and maximum-velocity settings, and the include and exclude layer masks. `MovePosition`, `MoveRotation` and `Move` set the stored pose, `Sleep`, `WakeUp` and `IsSleeping` set and read a stored flag, and `GetPointVelocity` and `GetRelativePointVelocity` calculate from the stored values. `AddForce`, `AddRelativeForce`, `AddTorque`, `AddRelativeTorque`, `AddForceAtPosition`, `AddExplosionForce` and `SetDensity` do nothing, and `GetAccumulatedForce` and `GetAccumulatedTorque` return zero. `SweepTest` returns false with a default hit, `SweepTestAll` returns an empty array and `ClosestPointOnBounds` returns the stored position. |
| `Collider`, `BoxCollider`, `SphereCollider`, `CapsuleCollider`, `MeshCollider` | `AddComponent` throws `NotSupportedException` naming the component type. | `Physics`, `PhysicsScene` | Settings such as `gravity`, `defaultContactOffset`, `sleepThreshold`, `bounceThreshold`, `simulationMode`, `queriesHitTriggers` and the solver defaults are stored and read back. Every query reports an empty world: `Raycast`, `Linecast`, `SphereCast`, `CapsuleCast`, `BoxCast` and the `Check*` queries return false with a default `RaycastHit`, the `*All` and `Overlap*` queries return empty arrays, and the `*NonAlloc` queries and the `PhysicsScene` array overloads return 0 and leave the buffer untouched. `Simulate`, `SyncTransforms`, `RebuildBroadphaseRegions` and `BakeMesh` do nothing. `ComputePenetration` returns false with zero direction and distance, and throws `ArgumentNullException` for a null collider. `ClosestPoint` transforms through the collider's local `ClosestPoint`. `IgnoreLayerCollision` and `GetIgnoreLayerCollision` (a layer outside 0 to 31 throws `ArgumentOutOfRangeException`) and `IgnoreCollision` and `GetIgnoreCollision` store the pairs and change no simulation. `ContactEvent`, `ContactModifyEvent` and `ContactModifyEventCCD` accept handlers that are never called. `defaultPhysicsScene` is a valid scene, `PhysicsScene.IsEmpty` is true (an invalid scene throws `InvalidOperationException`), and its step members do nothing. `GetCurrentIntegrationInfo` reports no integration. |

## Assets, web requests, JSON and command buffers

Some of these types work (`Resources`, `TextAsset`, `JsonUtility`, the upload and download handler objects). The others exist so that game code which references them loads, and where the engine does not do the work yet the member throws `NotSupportedException` naming itself.

| Type | Supported |
| --- | --- |
| `Resources` | `Load`, `Load<T>`, `LoadAll`, `LoadAsync`, `UnloadAsset`, `UnloadUnusedAssets`, `FindObjectsOfTypeAll`, `InstanceIDToObject`, `EntityIdToObject`, `InstanceIDIsValid` and `EntityIdIsValid`. Loads read the assets in the player's `Resources` folders by path without the extension, matched without regard to case, and return null or an empty array when nothing matches or the game has no player resources. A player's resources build `TextAsset`, `Texture2D`, `Sprite`, `SpriteAtlas`, `ScriptableObject` and `GameObject` assets; asking for an entry of any other class throws `NotSupportedException` naming the path and class. A `GameObject` is a prefab: `Resources.Load`, `Load<GameObject>`, `LoadAll<GameObject>` and `LoadAsync` return its root template, an inactive object with its children that belongs to no scene, is skipped by searches and never wakes, and loading the same path again returns the same object. `Object.Instantiate` clones it into the active scene, active when the prefab's root is active, and the clone's `Awake`, `OnEnable` and `Start` run as for any instantiated object; fields that pointed into the prefab point into the clone.
