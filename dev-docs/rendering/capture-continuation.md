# Two-segment capture continuation

A consumer may need a CPU result between two GPU segments, such as fitting shadow cascades from a depth reduction in the same frame. `SubmissionAuthority::begin_capture` reserves one logical frame after earlier queue work retires. It returns Busy while earlier work, preparation or configuration is active. Interactive frames continue to use the existing single-segment API.

Declare `CaptureWrites` before beginning. Prefix and suffix keys identify CPU resident state or registered GPU allocations with their generation. A suffix write that overlaps a prefix write requires explicit suffix ownership. Unkeyed CPU publications are rejected in captures. Use `Publications::stage_write` to stage a declared CPU edit. Ignored write errors still invalidate the segment, so no commands or edits from it can be submitted.

Stock same-frame depth-fitted scene captures provision celestial visibility targets at the capture extent before freezing the contract. Their radiance and depth allocations belong to the suffix, along with the resident velocity attachment when present. The later scene schedule reuses those allocations; scenes without celestial meshes allocate no visibility targets.

Move a frame snapshot into `begin_capture`. Include frame identity, configuration identity, camera, animation, jitter and all selected inputs and resource leases. Both preparation callbacks receive the same shared reference. Do not put host-mutable state inside this snapshot. The authority excludes unrelated preparation, submissions and configuration until the capture ends. Direct initialization queue writes remain subject to the existing initialization-only queue contract.

Prefix submission publishes only its staged edits. `CaptureContinuation::resume` waits for that submission and invokes the readback callback before suffix preparation. Readback callbacks receive the exact submission index and can use `BufferReadback::read_encoded` or `Readback::read_encoded`. Include `Readback::write_key()` in the copying segment's write set to declare its retained slot bookkeeping. CPU continuation calculations and suffix uploads belong in the suffix callback. Handles are consuming: a continuation cannot be resumed twice, and a suffix cannot be submitted twice.

`ResourceRegistry::compile_capture` validates the complete operation sequence and its producer versions before splitting it. It derives allocation-level write contracts from checked accesses. Operation order and StageIds are preserved. `CompiledOperations::encode` checks actual writes against the active segment before encoding any commands. Static suffix operations can use the compiled suffix directly. For readback-dependent uploads, prepare typed operations with the computed bytes in the suffix callback using the predeclared resource contracts. Encoder-only adapters must declare their resource writes with `Publications::write`; arbitrary raw encoder commands are not introspected.

After suffix submission, `SubmittedCapture::finish` waits for the suffix and performs final readback. Only successful completion reports `CaptureOutcome::Complete`. Final readback failure does not undo already submitted suffix state. No failed preparation publishes suffix edits.

Readback, preparation, write-contract and submission failures return typed errors. Retain a `CaptureObserver` to observe cancellation or drop when there is no return path. Dropping a submitted handle never waits on the event thread. It transfers the last ticket and frozen inputs to authority-owned cleanup. Hosts must poll the device and call `poll_captures` during idle iterations, or call `drain_captures` at shutdown. Draining waits for abandoned work; it returns Busy for a capture still owned by a caller. Retained readback slots become reusable after lease retirement, including copies that were dropped without being read. Device loss invalidates the generation, releases abandoned leases and keeps admission stopped. Create a new device and authority instead of recycling the lost generation.
