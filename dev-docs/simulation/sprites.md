# Native sprites and UI contributions

`world-simulation::presentation` owns sprite and orthographic camera descriptions, and `world-simulation::tilemap` owns tilemaps: a grid layout (cell size, gap, tile anchor), a palette of tiles and the cells using them. A tile draws at its cell's origin plus the anchor times the cell size, then its own transform. Sprite rectangles are pixels measured from the texture's bottom-left, pivots are normalized, and pixels-per-unit converts the rectangle into native XY metres. Sprite and tile transforms retain the complete object hierarchy matrix, including shear. Bounds remain in native coordinates.

With the `simulation` feature, `render-plan::simulation::extract_world` produces pathless contributions. Supply texture bytes in `SpriteTextures` using ordinary `SceneTexture` descriptions. Missing referenced textures fail when preparing the scene contribution. Extraction converts native XY geometry and cameras into scene XZ coordinates once. Camera queries and drawing use the same resolved view. The highest enabled active camera depth wins; equal depths retain the first camera. `CameraClear::SolidColor` and `Skybox` clear to the background color with its alpha preserved; `DepthOnly` and `Nothing` return an unsupported-field error, because a frame has one camera.

The built-in `SpriteUnlit` material selects the existing dynamic-quad straight-alpha pipeline. Tint is linear RGBA. Mark authored color textures as sRGB and coverage textures as linear. The shared scene target handles output encoding and 1x or 4x MSAA. Sorting uses ascending layer and order with stable submission ties. Screen overlays follow world quads, then use their own sorting keys.

With `ui`, pass the `extract_ui` output to `append_ui`. Coverage becomes white RGBA with the original alpha, then follows the same material and quad path. Overlay vertices use the selected camera's inverse projection. A layout from a different viewport is rejected; regenerate layout and extraction on resize.

`WorldSceneContribution::new` prepares the texture table and explicit quad corners for either headless scene rendering or `LiveFrame::from_world`. `SceneGpu::set_dynamic_contribution` replaces textures and geometry together. Rejected uploads retain the old contribution. `clear_dynamic` releases runtime texture, geometry and index-buffer ownership; dropping the resident scene also releases it.

Managed applications create immutable descriptors with `DisunityHost.CreateSprite`. `UnityEngine.SpriteRenderer` reads and writes the native component through generated bindings, including color, sprite, enabled, flips, sorting and world bounds. `Sprite` exposes rect, pivot, pixelsPerUnit and local bounds. Sorting layer IDs are numeric priorities; only the built-in `Default` layer has a supported name. Unsupported names fail explicitly. Sprite cloning retains immutable content and independently clones renderer state.

Mixed hosts call `DisunityHost::export_presentation(viewport, next_texture)` on the same loaded native image. Pass the first unused texture identity above the application's texture table. The engine extracts active sprites, tiles, the selected camera and clear, and Canvas/Text glyphs using that world's own FontBook. Generated bounded copy-outs carry immutable quad observations and linear RGBA coverage. `render-plan::simulation::from_presentation` combines these observations with application texture bytes before ordinary scene preparation. A prepared native frame is replaced by the next extraction and released on world unload. The narrower `export_sprites` API remains available for callers that only need renderer descriptors and matrices.

Managed Sprite content receives a native immutable identity. Assignment, repeated property reads, sharing between renderers and Instantiate resolve the same managed wrapper while a reference remains alive. Renderer tint and enabled state are independent of that identity. Serialized Color and Bounds fields retain their values, including in arrays and lists. Unsupported serialized types throw NotSupportedException before clone activation.

## Known limits

Texture replacement uploads each frame, and distinct explicit corners generally prevent draw grouping. The GPU tests check visible replacement and clear; they do not measure resident allocation retirement.
