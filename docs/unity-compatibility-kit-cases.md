# Compatibility-kit case catalog

**Design revision 1 · 54 proposed definitions · execution pending**

The [architecture and test plan](unity-compatibility-kit-architecture.md) explains the shared engine path. This catalog defines the public behavior and evidence needed to implement it. Each case has a stable ID and starts at contract revision 1. P0 establishes the first API/runtime/Snake slice; P1 adds Breakout, historical Pong or further shared-path checks; P2 follows those slices. A versioned CI baseline separately selects required cases.

## Profiles, evidence and pending decisions

Modern selects the 6000.3-shaped source profile; Legacy selects the separate 2017.1-shaped Pong profile. Shared cases run under both where applicable. The declarations are candidate contracts derived from the authored guide and local game requirements. Exact metadata and unresolved semantics need a recorded decision before promotion.

Guide links identify the expected-behavior source. A/B/C requirement IDs refer to the [comparison inventory](training-only-unity6-reference/game-comparison-inventory.json): A is Breakout, B is Snake and C is Pong. Ranges are inclusive. Game usage establishes a requirement; an approved expectation defines the assertion.

Declaration cases compile source forms and inspect independent assembly metadata. Behavior cases execute public managed calls against canonical Rust state. Content/visual/game cases add real importer, GPU and desktop resources. The four harness cases establish runner reliability and are reported separately from compatibility-facing results. Pass criteria use public values, callback records and actual contacts/pixels. Private game fields/helpers and configured mock returns cannot supply gameplay success evidence.

Dependencies identify capabilities. A missing in-scope provider is not-implemented, a profile exclusion is unsupported, and missing required content/tooling is blocked. Cases remain selectable during implementation. An absent result displays as unmeasured. A pending expectation produces an inconclusive attempt until its bounded contract is approved. The [Snake specimen](unity-compatibility-kit-fixture.example.json) demonstrates these distinctions for missing content and planned drivers.
